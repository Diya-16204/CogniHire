JVM Fatal Crash Logs (Safe to Delete)hs_err_pid<PID>.log (hs_err_pid5336.log, hs_err_pid9100.log, etc.): Automatically generated by the Java Virtual Machine (JVM) whenever the Java process suffers a fatal crash (e.g., Out of Memory error, segmentation fault, or native C/C++ library crash). The number indicates the process ID (PID) of the crashed Java instance.   replay_pid<PID>.log (replay_pid12880.log, replay_pid22244.log): Generated alongside fatal crashes when the JVM's Just-In-Time (JIT) compiler crashes. It captures compiler thread details to help reproduce the crash.Action: You can safely delete all hs_err_pid*.log and replay_pid*.log files. If your app is frequently crashing, open one of these files to see why the JVM died.


2. Startup Diagnosticsstartup-diagnostic.log: A log file created during application startup to track Spring Boot bootstrap duration, environment initialization, or failure diagnostics.


3. Build & Dependency Managementpom.xml: The central Maven configuration file defining Java runtime dependencies, Spring Boot   version (3.5.6), plugins, and build rules.
   mvnw & mvnw.cmd: Maven Wrapper executable scripts for Unix/Linux (mvnw) and Windows (mvnw.cmd). They allow running Maven commands without requiring Maven to be installed globally on your system.


4. Build Artifacts & Containerizationtarget/: Maven's output directory where compiled .class files, generated JAR binaries, and temporary build assets are stored after running mvn compile or mvn package.
 Dockerfile: Defines the container build environment used to bundle and run your Spring Boot API in Docker.
