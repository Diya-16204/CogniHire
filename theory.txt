### 1. Local Code Execution Engine (`.piston-data/` Directory)

The `.piston-data` folder is generated by the Piston Code Execution Engine container when running locally via Docker. Piston uses this directory to store, build, and execute language runtimes in isolated environments.

* **`packages/python/3.12.0/`**: The complete installed Python 3.12.0 runtime environment managed by Piston's package installer (`ppman`).
* **`bin/`**: Standard Python executables (`python3`, `python3.12`, `pip3`, `2to3`, `f2py`) used to run candidate code inside the containerized sandbox environment.
* **`lib/`, `include/`, `share/`**: Core standard library dependencies, headers, and modules required for Python execution.
* **`metadata.json` & `pkg-info.json`**: Piston metadata tracking runtime package versions, permissions, and language execution aliases.
* **`environment` & `build.sh`**: Shell scripts and environment bindings executed by Piston to initialize the sandbox before executing candidate code.
* **`run` script**: The internal wrapper script Piston calls to execute submitted candidate code snippets (such as `test.py`).

### 2. Root Configuration & Infrastructure Files

These files manage your local developer setup, container orchestration, and cloud deployment pipelines:

* **`docker-compose.yml`**: Defines the local multi-container stack (typically PostgreSQL, Redis, and the main Piston container).
* **`docker-compose.piston.yml`**: A dedicated Docker Compose definition used to run or reset the Piston code execution API independently without restarting the entire database stack.
* **`render.yaml`**: Infrastructure-as-Code (IaC) deployment blueprint for deploying the Spring Boot backend to Render.
* **`.env` / `.env.example`**: Local environment variables (database credentials, Redis hosts, execution endpoint URLs, and OpenAI keys).
* **`run`**: A custom local orchestration shell script used to simplify common developer commands (e.g., building, seeding, or starting Docker containers).
* **`README.md`**: Project documentation covering local setup and environment configuration.

### 3. IDE & Repository Metadata (`.idea/`)

* **`.idea/`**: IntelliJ IDEA project configuration folder containing inspection settings (`inspectionProfiles/`), module definitions (`modules.xml`, `CogniHire-main.iml`), version control mappings (`vcs.xml`), and local workspace settings (`workspace.xml`).
